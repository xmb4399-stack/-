# 老年视频播放器 · 安卓版

把原来那个 PyQt5 的《老年人播放器 美观版.py》移植到安卓，打包成能直接装在手机上的 APK。

界面用 Kivy 重写，业务逻辑（目录结构、播放记录、断点续播）基本从原版原样搬过来。
播放内核换成了 **libVLC**，所以 RMVB / WMV / AVI / FLV 这些安卓系统解不了的老格式
也能直接播放（详见下面「手机能放哪些格式」）。

> **安装包会比一般小应用大一些（实测 58MB）**，因为里面带了完整的解码库——
> 这也是 MX Player、VLC 这类「什么都能放」的播放器体积都很大的原因。
> 如果你不在意格式支持、只想要个小包，见常见问题里的「如何去掉 VLC 内核」。

## 先看这个：怎么拿到 APK

**你的电脑上编译不了 APK。** 打包安卓应用需要 Linux + JDK + Android SDK/NDK，
而且你这台机器的 WSL 被安全策略禁用了，Docker 也没装。

所以走**云端编译**：把这份代码放到 GitHub 上，让 GitHub 的 Linux 机器帮你编译，
编译完直接下载 APK。整个过程你只需要点几下。

### 第 1 步：把代码传到 GitHub

**方式 A（推荐，最稳）：GitHub Desktop**

1. 到 https://desktop.github.com 下载安装 GitHub Desktop，登录你的 GitHub 账号
2. 菜单 `File → Add local repository`，选中 `elder-video-player` 这个文件夹
3. 它会提示「这不是一个 git 仓库」，点 `create a repository`
4. 点右上角 `Publish repository`
   - **把 `Keep this code private` 取消勾选**（公开仓库编译时间免费且无限）
   - 点 `Publish repository`

**方式 B：网页上传（有坑，见下面第 4 点）**

1. 打开 https://github.com/new ，起个名字，创建空仓库
2. 进入仓库，点 `Add file → Upload files`
3. 把 `elder-video-player` 文件夹里的**所有内容**拖进去（注意：要拖文件夹里面的东西，
   不是拖 `elder-video-player` 这一层）
4. 点 `Commit changes`

> ⚠️ **网页上传会跳过所有「点开头」的文件夹**，`.github` 和 `.gitignore` 都传不上去。
> 少了 `.github`，Actions 页面只会显示一堆推荐模板、没有「编译安卓 APK」、也就没有黄点。
>
> 补救办法（两分钟）：打开
> `https://github.com/你的用户名/你的仓库名/new/main` ，
> 在文件名框里原样输入 `.github/workflows/build-apk.yml`（输入斜杠会自动变成文件夹），
> 再把本仓库里 `.github/workflows/build-apk.yml` 的内容整段粘进去，点 `Commit changes`。
>
> 传完到仓库首页确认一下：能看到 `.github` 这个文件夹就对了。
> 用方式 A（GitHub Desktop）不会有这个问题。

### 第 2 步：等它自动编译

推送完成后：

1. 打开你的仓库页面，点上面的 **Actions** 标签
2. 会看到一条 `编译安卓 APK` 正在跑（黄色小圆点在转）
3. **第一次编译大约 40～60 分钟**（要下载 Android SDK 和 NDK，只有第一次慢）
   之后的编译因为有缓存会快很多 —— 实测第二次只用了 **12 分钟**
4. 改 README、改文档这类**不会**触发编译；只有源码和 `buildozer.spec` 变了才编译。
   想手动重跑就点右边的 `Run workflow`

### 第 3 步：下载 APK

1. 等它变成绿色的对勾 ✓
2. 点进那次运行记录，页面**拉到最下面**
3. 在 `Artifacts` 区域点 **elder-player-apk** 下载
4. 下载下来是个 zip，解压出来就是 `.apk` 文件

### 第 4 步：装到手机上

1. 把 APK 传到手机（微信文件传输助手、数据线、网盘都行）
2. 在手机上点开安装。系统会提示「未知来源」，允许一下即可
   （小米/华为/OPPO/vivo 一般叫「允许安装未知应用」）
3. 装好后先打开一次，**跟着应用里的引导页把权限给上**（见下面「第一次使用」）

## 第一次使用：三个必须做的动作

装好后打开，如果直接进了主页，说明一切正常，跳到第 3 步。

### 1. 授予「所有文件访问权限」

应用打开后会停在「还差最后一步」这个页面，点 **去授权**。

系统会跳到「所有文件访问权限」的开关页，把它打开，然后返回应用。

> 为什么要这个权限？
> 安卓 11 以后应用默认只能读系统媒体库收录的文件。
> 老人的视频很多是 RMVB、FLV 这类老格式，系统不认，只有拿到这个权限才读得到。
> 另外，有了它应用才能自己创建文件夹。

### 2. 建文件夹、拷视频

回到引导页，点 **帮我建文件夹**，应用会在手机上建好：

```
/storage/emulated/0/Movies/老人视频/
```

然后用手机自带的「文件管理」App，把视频拷进去。**目录结构必须是这样**：

```
老人视频（或您自定义的主文件夹）/
├── 戏曲/
│   ├── 女驸马/
│   │   ├── 女驸马01.mp4
│   │   └── 女驸马02.mp4
│   └── 天仙配/
│       └── 天仙配.mp4
└── 电视剧/
    └── 西游记/
        ├── 01.mp4
        └── 02.mp4
```

三层：**主文件夹 / 分类 / 剧集 / 视频**。

- 「戏曲」「电视剧」这两个名字对应主页上那两个大按钮
  （老手机里文件夹还叫「黄梅戏」也能认，不用改名）
- 分类下面直接放视频也行，不强制要求剧集这一层
- 剧集文件夹里放视频文件，文件名随便起，会按「自然顺序」排列
  （第2集 排在 第10集 前面，原版是按字符串排的，顺序是乱的）

### 3. 回到应用点「重新扫描」

视频就出来了。

> 想换个文件夹？主页 → 设置 → 选文件夹。
> **App 默认横屏**（横过来拿手机，三个大入口并排，一屏点完不用滚动）。
> 想改成竖屏：设置 → **打开时的屏幕方向** → 点「竖屏」。

## 手机能放哪些格式？

这个版本**内置了 VLC 的播放内核**（libVLC），所以主流格式基本都能直接放：

| 格式 | 能不能放 |
|---|---|
| `.mp4` `.mkv` `.webm` `.mov` `.3gp` `.ts` | ✅ 播放内核和你平时用的 VLC 播放器是同一个，最稳 |
| `.rmvb` `.rm` `.flv` `.wmv` `.avi` | ✅ 以前安卓系统解不了，现在换成 VLC 内核后可以直接放 |

> 市面上「什么格式都能放」的安卓播放器（MX Player、VLC），靠的也是**自带一套
> 解码器**——安卓系统本身确实只认 H.264。区别只是它们把 FFmpeg 装进 App，
> 而这里把 VLC 装进 App，原理一样。代价是安装包会大一些，
> 详见常见问题里的「安装包变大了吧？」。

设置里有个开关 **增强播放器（支持更多格式）**，默认是开的：

- **开着**：用 VLC 内核，RMVB / WMV / AVI / FLV 都能放
- **关掉**：退回安卓系统播放器，只放得了 H.264 的 MP4/MKV，
  但 App 会小很多、也省电一点。放不了的格式**不会出现在列表里**
  （免得老人点了一个播不出来干着急）。想看全部文件？
  设置 → **显示可能无法播放的格式** → 打开。

**VLC 内核起不来时会自动降级**，退回系统播放器接着播，不会卡死在黑屏上。

### 顺便说一句：转成 MP4 仍然是更省心的选择

内置 VLC 之后，老格式已经能直接放了，不转也行。但如果视频很多、
或者老人的手机比较老（内存小、处理器弱），在电脑上**预先转成 MP4**
仍然更流畅、更省电，视频文件本身也会小一圈。

项目里带了一个转换脚本 `tools/convert_videos.py`，在电脑上跑一次就好。

它比一般转格式工具多做了一件事：**先看文件里到底是什么编码**。
如果视频本来就是 H.264（很多 `.flv`、一部分 `.avi` 都是），它只换个外壳，
**几秒钟完事，画质一点不损失**；只有编码确实是老的（RMVB 的 RV40、
WMV 的 WMV3、AVI 里的 DivX 等）才重新编码。

```bash
# 第一次用，装个便携版 ffmpeg（不用自己配环境）
pip install imageio-ffmpeg

# 先看一眼都有什么、要不要转（不写任何文件）
python tools/convert_videos.py --src "D:/老人的视频" --dry-run

# 正式转换（不删原文件）
python tools/convert_videos.py --src "D:/老人的视频"
```

转好的放在**源文件夹同级的「<源文件夹名>_手机版」**里，目录结构原样保留，
整个拷到手机的 `存储/Movies/老人视频/` 就行。

| 参数 | 作用 |
|---|---|
| `--max-height 720` | 限制最高 720p。老人机播 1080p 吃力，压一下更流畅、体积小很多 |
| `--deep` | 连 `.mp4` / `.mkv` 也一并检查 |
| `--dst "E:/转好的"` | 自己指定输出位置 |
| `--jobs 4` | 同时转 4 个（电脑核多更快，但看不到单个文件的进度） |

中途中断没关系，同样的命令再跑一次会接着来，已经转好的自动跳过。

> **为什么 `--deep` 有用**：有些 `.mp4` 看着正常，里面却是
> `yuv444p` 这种小众像素格式——电脑上能放，手机的硬解器直接黑屏。
> 脚本会把这些也揪出来重转。这是手机端最容易踩、又最难看出来的一个坑。

> 不想用脚本也行，格式工厂 / HandBrake 都可以，输出选 MP4、编码选 H.264。
> 但记得把**像素格式**设成 `yuv420p`，这是手机硬解的前提。

## 和原版比，改了什么

### 保留的

- 「主文件夹 / 分类 / 剧集 / 视频」四层结构
- 主页三个大按钮：戏曲（红）、电视剧（蓝）、历史播放（橙）
- 连续看满 **3 分钟** 才写入播放记录，续播时**回退 10 秒**
- 播放记录按剧集去重，只留最近一条
- 整个配色：浅蓝渐变背景、白色圆角卡片、大字号大按钮
- 播放界面那两个自定义颜色：暂停键 `#CED592`、返回键 `#FDCD60`
- 设置里能调字号和按钮大小

### 改掉的（都是必须改的）

| 原版 | 现在 | 原因 |
|---|---|---|
| PyQt5 / QtMultimedia | Kivy + libVLC（可降级到安卓原生 MediaPlayer） | PyQt5 官方不支持安卓，没有别的路 |
| OpenCV 抽缩略图 | 安卓 `MediaMetadataRetriever` | OpenCV 打包进安卓极难，原生 API 零依赖 |
| 配置存在视频文件夹的 `.player_config` | 存在应用私有目录 | 安卓 11+ 不允许应用往 `/sdcard` 写文件 |
| 桌面 `/Desktop/老人视频` | 手机 `存储/Movies/老人视频` | 安卓没有「桌面」这个概念 |
| `os.path` 字符串排序 | 自然排序 | 原版第 10 集排在第 2 集前面 |
| 每次播放位置变化都存盘 | 每 5 秒存一次 | 手机上太耗电 |

### 新增的

- **内置 VLC 播放内核**：RMVB / RM / WMV / AVI / FLV 免转码直接播放；
  内核起不来会自动降级到系统播放器，并在播放中也能无缝切换（记住进度）
- **主页图标可以换成自己的照片**：设置 → 主页图标 → 上传
  （选图页是整屏大格子，**带图片缩略图**，目录名显示成「相机相册（DCIM）」这样的中文，
  不用认英文路径；横屏手机太矮时照片格子会自动收掉文件名，把地方全留给照片；
  手机会自动把照片**转正**再存，不会躺倒；
  存之前缩到 512 像素，不占地方；随时能点「默认」还原）
- **打开时的屏幕方向可选横屏 / 竖屏**：设置 → 打开时的屏幕方向
- 播完一集**自动播下一集**
- 播放时**屏幕不熄灭**
- **主页三个大入口并排摆开**，一屏点完不用滚动（竖屏时自动换成三行大卡片）
- **音量用按钮调**（减 － / 喇叭 / 加 ＋，喇叭图标画得又大又清楚，静音时自动变成没声波的喇叭），
  直接调**系统媒体音量**，不用再去找手机侧键
- **返回键一律在屏幕底部**，单手拇指够得到
- 安卓返回键可以逐层退回，不会一点就退出应用
- 切到后台自动暂停
- 设置页内置**文件夹浏览**（不需要在手机上敲路径）
- 完全放不了的时候有**引导页**，一步步告诉你该干什么

```

├── elder_theme.py             配色、渐变、圆角卡片、中文字体、公共控件
├── elder_thumbs.py            缩略图生成（安卓原生抽帧 + 后台线程 + 磁盘缓存）
├── elder_vlc.py               libVLC 播放内核封装（接口和 Kivy 的 Video 完全一样）
├── assets/
│   ├── NotoSansSC-Regular.otf 中文字体（思源黑体，OFL 协议）

└── tools/
    ├── make_assets.py         重新生成图标（纯 Python 写 PNG，不依赖 Pillow）
    ├── convert_videos.py      把 rmvb/flv/wmv/avi 等老格式批量转成 mp4
    ├── trim_libvlc_abis.py    按目标架构裁剪 libVLC 解码库（编译前自动跑）
    ├── smoke_test.py          逻辑 + 界面冒烟测试（88 项，含字体字形检查）
    ├── vlc_test.py            libVLC 封装层的测试（61 项）
    ├── screenshot.py          把各个界面截成图（tools/shots/*.png，共 12 张）
```

### 想在电脑上先跑跑看

```bash
pip install "kivy[base]" ffpyplayer pillow fonttools
python tools/smoke_test.py     # 88 项检查
python tools/vlc_test.py       # 61 项检查（libVLC 封装层，不需要真机）
python tools/layout_check.py   # 16 种屏幕尺寸（手机 + 平板，横竖都有）× 8 个界面的排版体检
python tools/screenshot.py     # 截 12 张图，肉眼看排版
python main.py                 # 直接运行
```

电脑上跑主要是验证界面和逻辑，**真正的视频播放只能在手机上验**。
（装上 `ffpyplayer` 之后桌面也能放 mp4 了，但和手机上的解码路径不是一套。）

> 关于字形：内置字体是思源黑体（Noto Sans SC），**不含 emoji**。Kivy 不做字体
> 回退，字体里没有的字符会显示成空心方框。界面上的符号一律用字体里有的
> （`▶ ⇄ ≡ ▣ ❖ ‖ ◀◀`），`smoke_test.py` 里有一项专门查这个。
> 音量那个喇叭**不是字符**，是用 Pillow 现画出来的贴图（矢量图标字体里的喇叭
> 字形大多没有，硬塞只会变方框；自己画还能保证喇叭口和声波分得开，
> 静音时把声波去掉）。

> `vlc_test.py` 用假的播放器/媒体对象替换掉真 libVLC，把「探测 → 挂载画面 →
> 播放中失败降级 → 释放资源」这条链路完整跑了一遍，
> 包括坐标系翻转、后台切回来重挂画面这些容易出错的地方，所以不需要真机。

### 关于屏幕方向

`buildozer.spec` 里写的是 `orientation = all`，**不能改成 landscape**。

原因：用户在设置里可以选横屏还是竖屏。manifest 要是写死了 landscape，
系统层面就锁住了，设置里的「竖屏」点了也不会生效。
方向由 `main.py` 启动时按设置调 `setRequestedOrientation` 钉住。

主页两套排法都保留了：横屏是一排三个方块，竖屏是一列三行整行卡片，
按窗口比例自动判断，切方向时立刻换过来。

### 想换 CPU 架构

默认只编译 `arm64-v8a`（2016 年之后的手机基本都是）。

如果老人的手机比较老、装不上，到 GitHub 的 **Actions → 编译安卓 APK → Run workflow**，
在 `目标 CPU 架构` 那里选 `arm64-v8a,armeabi-v7a` 再跑一次。

> 换了架构**不用手动改别的**：工作流编译前会自动跑一次
> `tools/trim_libvlc_abis.py`，按目标架构把用不到的 libVLC 解码库剔出去。
> 本地手动编译的话，改完 `android.archs` 记得先跑一下这个脚本。

## 常见问题

**Q：编译失败了怎么办？**
第一次编译失败最常见的原因是网络抖动（要下载 1GB 多的 Android SDK）。
到 Actions 页面点 `Re-run all jobs` 重试一次，通常就好了。

**不用下载日志也能查原因**：编译失败时，工作流会自动把最后 200 行报错写进仓库根目录的
`ci-last-error.md`，打开那个文件就能看到红字在哪。把这个文件的内容发我即可。

**Q：装的时候提示「应用未安装」？**
多半是 CPU 架构不对。按上面的方法编译一个 `armeabi-v7a` 版本再试。

**Q：装好了但看不到视频？**
按顺序检查：
1. 设置页里「存储权限」显示的是不是「已获得」
2. 视频是不是真的在 `Movies/老人视频/分类/剧集/` 下面
3. 去设置里把「显示可能无法播放的格式」打开，看看文件到底有没有被扫到
4. 如果列表里有、点了却黑屏：设置 → 关掉「增强播放器」再试一次
   （这一步是在系统播放器和 VLC 内核之间切换，能看出是哪一层的问题）

**Q：视频能播但没声音？**
播放界面里的音量条是直接调**系统媒体音量**的，先看看是不是被拉到 0 了。
还是没声音的话，检查手机的「媒体音量」（按音量键时出现的那个条）。

**Q：App 里到底是怎么放出 RMVB 的？**

内置了 **libVLC**（VLC 播放器的安卓内核）。整个过程是这样的：

1. App 启动时先探测 libVLC 在不在、能不能用
2. 能用 → 用一个安卓原生 `SurfaceView` 承载 VLC 的画面，
   把它垫在 Kivy 界面**下面一层**、再让触摸事件穿透回 Kivy 的按钮
3. 万一 libVLC 加载失败、或者画面挂不上去 → 2 秒内自动切回系统播放器，
   并且**记住当前播放进度**，从刚才的位置接着播

所以最坏的情况就是「和以前一样只能放 MP4」，不会变成一个打不开的 App。

**Q：安装包变大了吧？**

是。libVLC 的解码库本身压缩后还有 19MB 左右一个架构，
默认只保留 `arm64-v8a`（2016 年后的手机都是这个），
把用不上的 `x86` / `x86_64` / `armeabi-v7a` 剔除掉了，省下约 60MB。

实测：不裁剪是 **122MB**（4 种架构全在），裁剪后 **58MB** ——
换来的是所有主流格式免转码直接放。

> 这个裁剪依赖 `buildozer.spec` 里的 `android.add_packaging_options`
> 配合 AGP 8 的 `jniLibs { excludes += ... }` 写法，写法有三个坑，
> 详见 `buildozer.spec` 里那段注释和 `tools/trim_libvlc_abis.py` 开头。
> **别把它改回 `exclude 'lib/x86/*.so'` 那种老写法**，改回去 APK 会默默变回 122MB。
如果不想要这个体积，把 `buildozer.spec` 里的
`android.gradle_dependencies` 那一行删掉、重新编译即可，
App 会自动回到系统播放器模式（`elder_vlc.py` 探测不到就降级，不用改别的）。

**Q：libVLC 的授权会不会有问题？**

不会。libVLC 是 **LGPLv2.1+**，通过动态链接（Gradle 依赖，不是静态编译进去）
使用是明确允许的，不要求本应用开源。这一点和 FFmpeg 的 GPL 有本质区别。

**Q：能不能传到应用商店？**
不建议。应用申请了「所有文件访问权限」，Google Play 对这个权限卡得很严。
自己用、给家里人用，直接装 APK 就好。
